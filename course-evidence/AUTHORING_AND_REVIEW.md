# Content production and review workflow

Review method: AI source-by-source editorial review; no claim of human sign-off or gameplay testing.

## Reusable authoring prompt

Given one player question, its observed demand evidence and a dated source packet, write one English guide using the existing MDX frontmatter and renderer format. Start with the shortest supported answer. Add prerequisites, numbered actions, expected result, troubleshooting only when supported, source URLs, version/date and related existing guides. Keep existing URLs and anchors. For a boss use supported mechanics and tactics; for an item use location and prerequisites; for troubleshooting separate developer fixes from optional diagnostic suggestions. Distinguish planned features, community reports and observed behavior. Never invent values, codes, button sequences, dates or personal testing. Omit unsupported steps or state exactly what remains unknown. Merge synonymous intents and use existing pages when they answer the same question. Do not pad to a fixed word count.

## Batch process

1. Maintain at least ten planned pages with query/question, source, URL and editorial status.
2. Group a small number of related pages per batch.
3. Review every page for provenance and at least five in detail for content; preserve reviewer type and findings.
4. Validate frontmatter, duplicate slugs, citations, links, metadata and English output.
5. Build and preview the actual website before publishing.
6. Update existing pages on version changes; use GSC queries for the next batch.

## Monitoring

Record the exact hostname and report dates. Separate ownership, sitemap processing, indexed pages, impressions/clicks and GA page views. Internal QA is not organic acquisition. If no useful query exists, check technical access and revisit after day 7/day 14. No revenue or indexation guarantee.
